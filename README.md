# ניהול משימות — גרסה פרטית (Supabase + PWA)

גרסה חדשה של מערכת ניהול המשימות, שנבנתה מאפס לפי מסמך השכפול, לשימוש מהמחשב ומהטלפון.

- **צד שרת:** Supabase (Postgres, Auth, Storage, Realtime, Edge Functions). כל הלוגיקה העסקית (חזרתיות, אוטומציות, תלויות, היסטוריה) רצה **בתוך מסד הנתונים** כטריגרים, כך שהיא עובדת מכל מכשיר.
- **צד לקוח:** React 18 + TypeScript + Vite + Tailwind, כ-PWA שמותקן כאפליקציה בטלפון.

```
tasks-personal/
├── supabase/
│   ├── migrations/      סכמה + RLS + טריגרים, פונקציית ייבוא, Storage + Realtime
│   ├── functions/       push-reminders (תזכורות Push), ics (יומן חיצוני)
│   ├── cron.sql         תזמון (להריץ אחרי פריסת הפונקציות)
│   └── config.toml
└── web/                 האפליקציה
```

---

## 1. הקמת Supabase (פעם אחת, כ-15 דקות)

1. צור פרויקט ב-[supabase.com](https://supabase.com) (התוכנית החינמית מספיקה). אזור מומלץ: **Frankfurt (eu-central-1)**, הכי קרוב לישראל.
2. **SQL Editor** ← הרץ את שלושת הקבצים מ-`supabase/migrations/` **לפי הסדר** (0001 ← 0002 ← 0003).
   אפשר גם דרך ה-CLI: `supabase link --project-ref <ref>` ואז `supabase db push`.
3. **Authentication ← Sign In / Providers ← Email:** השאר את Email מופעל. אם אתה לא רוצה מייל אימות, כבה את "Confirm email".

## 2. הרצה מקומית

```bash
cd web
cp .env.example .env      # מלא את VITE_SUPABASE_URL ו-VITE_SUPABASE_ANON_KEY (Project Settings → API)
npm install
npm run dev               # http://localhost:5173
```

בפעם הראשונה לחץ **"יצירת חשבון"**. החשבון נוצר עם שני מרחבים (עבודה / אישי), נושא בסיסי בכל אחד, ושתי תוויות.

> 🔒 **חשוב:** אחרי שיצרת את החשבון שלך, חזור ל-**Authentication ← Providers ← Email** וכבה את **"Allow new users to sign up"**, כדי שאף אחד אחר לא יוכל להירשם. גם אם מישהו יירשם, ה-RLS מבטיח שהוא לא יראה את הנתונים שלך.

## 3. פריסה (כדי לגשת מהטלפון ומכל מקום)

האפליקציה היא אתר סטטי, וכל פלטפורמת אירוח חינמית מתאימה.

**Cloudflare Pages / Netlify / Vercel:**
- תיקיית שורש: `web`
- פקודת build: `npm run build`
- תיקיית פלט: `dist`
- משתני סביבה: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_VAPID_PUBLIC_KEY`
- קבצי ה-fallback של SPA כבר כלולים (`public/_redirects`, `vercel.json`).

ב-Supabase ← **Authentication ← URL Configuration**, הוסף את כתובת האתר ל-Site URL.

**בטלפון:** פתח את הכתובת ← באנדרואיד: תפריט ← "התקן אפליקציה". באייפון: ספארי ← שיתוף ← "הוסף למסך הבית".

## 4. התראות Push ותזמונים

```bash
npx web-push generate-vapid-keys          # נותן Public + Private

supabase secrets set \
  VAPID_PUBLIC_KEY=<public> \
  VAPID_PRIVATE_KEY=<private> \
  VAPID_SUBJECT=mailto:<המייל שלך> \
  CRON_SECRET=<מחרוזת אקראית ארוכה>

supabase functions deploy push-reminders --no-verify-jwt
supabase functions deploy ics --no-verify-jwt
```

- הוסף את `VITE_VAPID_PUBLIC_KEY=<public>` ל-`.env` ולמשתני הסביבה של האירוח.
- ערוך את `supabase/cron.sql`: הכנס את כתובת הפרויקט ואת ה-`CRON_SECRET`, והרץ אותו ב-SQL Editor. הוא מפעיל:
  - אוטומציות "תאריך היעד הגיע" כל 10 דקות.
  - תזכורות Push כל דקה, וסיכום בוקר בשעה שתבחר בהגדרות.
- באפליקציה: **הגדרות ← התראות ← "התראות במכשיר הזה"**, ואז "שליחת ניסיון". צריך להפעיל בכל מכשיר בנפרד.

## 5. ייבוא נתונים

**הגדרות ← ייצוא וייבוא ← ייבוא…**
- הייבוא תומך בקובץ הייצוא של הגרסה הקודמת: JSON (נתונים בלבד) או ZIP מלא (`data.json` + `documents/`). הוא סלחני למבנים שונים, ומציג תצוגה מקדימה עם ספירות ואזהרות לפני שהוא מייבא.
- בוחרים לאיזה מרחב לייבא, ואם למזג או להחליף.
- ה-IDs נשמרים, אז ייבוא חוזר לא יוצר כפילויות.

> ⚠️ **לגבי נתונים מהעבודה:** המערכת בעבודה יושבת ברשת סגורה. **לפני שמוציאים ממנה קובץ ייצוא, צריך אישור מפורש מקב"ט / אבטחת מידע.** גם שמות משימות ונושאים יכולים להיות מידע מסווג או רגיש, והוצאה שלהם לענן פרטי עלולה להיות הפרה של הנהלים. בלי אישור כזה, עדיף להתחיל ממערכת ריקה ולהכניס רק משימות אישיות.

## מה חדש לעומת הגרסה הקודמת

| נושא | קודם | עכשיו |
|---|---|---|
| גישה | רשת סגורה / Tailscale | מכל מקום, עם התחברות מאובטחת |
| סנכרון | — | **Realtime**: שינוי בטלפון מופיע מיד במחשב |
| אופליין | קריאה בלבד | **קריאה + כתיבה**: השינויים נכנסים לתור ומסונכרנים כשהחיבור חוזר (מחוון בסיידבר) |
| מובייל | רספונסיבי | **ניווט תחתון, כפתור + צף, החלקה** (שמאלה = השלמה, ימינה = מחר), גיליונות תחתונים, Quick Add עם צ'יפים של תאריך ונושא |
| התראות | רק כשהטאב פתוח | **Push מהשרת**: מגיעות גם כשהאפליקציה סגורה, עם "X דקות לפני" לכל משימה, וסיכום בוקר |
| הפרדה | — | **מרחבים** (עבודה / אישי / הכל) עם מעבר בלחיצה |
| לוגיקה | Python | טריגרים ב-Postgres: חזרתיות, אוטומציות (עם מניעת לולאות), מניעת מעגלי תלויות, היסטוריה |
| קבצים | דיסק מקומי | Supabase Storage פרטי, לכל משתמש תיקייה משלו (RLS) |
| עיצוב | — | ליטוש: עומק עדין בכרטיסים, גרדיאנטים באייקונים, מיקרו-אנימציות (השלמה, כניסה), מצב כהה מאוזן יותר, זכוכית בניווט התחתון |

כל הפיצ'רים מהמסמך המקורי נשמרו: טבלה עם קבוצות וגרירה, קנבן, יומן עברי עם זמני שבת, ציר זמן עם תלויות, ספרינטים עם Burndown, מטרות, הרגלים עם רצף, Wiki עם `[[קישורים]]`, אוטומציות, פלטת פקודות, קיצורי מקלדת, Undo, מצב פוקוס, תכנון וסיכום יומי, ICS.

**לא הועבר:** בוט טלגרם. ה-Push מחליף אותו לתזכורות. אם תרצה אותו, אפשר להוסיף אותו כ-Edge Function.

## בדיקות

```bash
cd web && npm test         # 49 בדיקות: Quick Add (42 מקרים), תאריכים, סינון ומיון, רצף הרגלים, ייבוא
```

הסכמה, הטריגרים וה-RLS נבדקו מול Postgres 16: חזרתיות, מניעת כפילות מופע, איפוס צ'קליסט, מעגל תלויות, אוטומציות ומניעת לולאה, טיימר יחיד, הפרדת משתמשים, וייבוא חוזר.

## מלכודות שכדאי להכיר

1. **תאריכים מקומיים תמיד.** `isoDate()` ולא `toISOString()`. בשרת משתמשים ב-`today_il()`.
2. **אוטומציות לא מפעילות אוטומציות** (הדגל `app.in_automation`). ייבוא לא מפעיל טריגרים (הדגל `app.importing`).
3. **מחיקה עם Undo:** המחיקה בשרת נשלחת רק אחרי 6 שניות.
4. **מזהים נוצרים בצד הלקוח** (20 תווי hex, כמו בגרסה הישנה). זה מאפשר עבודה אופליין וייבוא בלי התנגשויות.
5. **שינוי סכמה = קובץ migration חדש**, לא עריכה של קובץ קיים.
6. Supabase מחזיר עד 1,000 שורות לבקשה, והטעינה עושה דפדוף אוטומטי.
7. `npm run typecheck` מריץ בדיקת טיפוסים מלאה. ה-build עצמו (`vite build`) לא חוסם על שגיאות טיפוסים.
